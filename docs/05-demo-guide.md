# 05 · DEMO 使用说明

**版本：v0.2（2026-11-11）** ｜ 阶段 1 收尾 + 阶段 2 主体完成。跑在绿联 NAS 的 Hermes 容器里，服务监听 8000（宿主已映射 8000）。

## 1. 打开

| 端 | 地址 | 登录 | 建议设备 |
|---|---|---|---|
| 调度端 | `http://192.168.1.210:8000/dispatcher` | 调度口令 | 电脑浏览器 |
| 台账管理 | `http://192.168.1.210:8000/admin` | 调度口令 | 电脑浏览器 |
| 大屏看板 | `http://192.168.1.210:8000/board` | 调度口令 | 大屏/电脑 |
| 轨迹回放 | `http://192.168.1.210:8000/track` | 调度口令 | 电脑浏览器 |
| 司机端 | `http://192.168.1.210:8000/driver` | 手机号 | 手机浏览器（同一 WiFi） |
| 乘客端 | `http://192.168.1.210:8000/rider` | **免登录** | 手机浏览器 |

登录入口统一在 `/login`：司机填**登记手机号**（演示数据见第 5 节，如张伟 13800000001），
调度员填**口令**。口令未配置时首启自动生成，查看：

```bash
cat /mnt/projects/Dispatcher/data/.dispatcher_pass
```

> 也可以在 `.env` 里设 `DISPATCHER_PASSWORD=*** 然后重启服务，用固定口令。
> token 有效期 12 小时，过期自动跳回登录页。

打不开时依次排查：
1. 手机和 NAS 是否同一网段；
2. `curl http://192.168.1.210:8000/health`（在 NAS 上）—— 不通则容器内服务没起，看 `logs/server.log`；
3. 宿主 8000 是否被别的服务占用（`docker ps` 看端口映射）。

## 2. 三分钟演示脚本（建议两人：电脑 + 手机）

1. **调度端**先登录，看到高德地图上 4 辆车、7 个今日班次；左上角显示「实时连接正常（WebSocket）」。
2. **手机开乘客端**（免登录）：起点选「园区环线 A · 南门」，终点选「食堂」，人数 2，点**叫车**。
   → 页面立刻变成「等待接单」，并开始计时「已等 N 分钟」。
3. **司机端登录**（张伟 13800000001）：点**开始发车** → 点站点「2. A 栋」= 到站上报。
4. 回**调度端**：≤2 秒内地图上「D1234」跳到 A 栋（WebSocket 推送，无需刷新），
   右侧「待处理叫车」出现这条单并显示**预计 N 分钟送达** → 点**指派车辆** 或让司机端点**接单**。
5. **司机端**点「已接到乘客」→ 乘客端状态变「已上车」+ ETA；再点「送达完成」→ 乘客端显示已送达 🎉。
   末站可勾「末站到站后直接结束班次」或点「结束班次」。
6. 调度端底部**事件日志**看到全过程：`arrive / ride_new / accepted / boarded / done`（每条带操作人）。
7. 加分项：
   - **看板** `/board`：在线率、准点率、班次完成率大数字实时刷新；
   - **轨迹** `/track`：选刚才那个行程，点「▶ 回放」看车逐站移动（数据来自每次到站上报）；
   - **台账** `/admin` → 「地图画线路」：在地图上按顺序点几个点、命名，「生成站点」即新建一条线路。

> 位置是"到站触发"：车不动位置就不动，这正是设计（见决策 D6）。

## 3. 常用命令

```bash
cd /mnt/projects/Dispatcher

./run.sh                      # 本地起服务（带热重载，默认 8000）
.venv/bin/python scripts/reset_demo.py   # 清空演示数据、重新播种
tail -f logs/server.log       # 看服务日志

# Docker 部署（在 NAS 宿主上）
docker compose up -d --build
```

看门狗：cron `dispatcher-demo-watchdog`（每 10 分钟）跑 `/opt/data/scripts/ensure-dispatcher.sh`，
探活 `127.0.0.1:8000/health`，挂了自动拉起，健康时静默。

## 4. 这一版新增（v0.1 → v0.2）

- **高德地图**真实底图（复用 Where2Go 的 key，配在 `.env`；无 key 自动降级 SVG 示意图）
- **登录鉴权**：司机=手机号、调度员=口令、乘客免登录；越权操作一律 403
- **台账 CRUD** `/admin`：车辆/司机/线路/站点/班次全可增删改，带删除保护（已排班/有进行中订单的不可删）
- **地图画线路**：点选坐标 → 命名 → 批量生成站点（Q5）
- **排班冲突检测**：同车/同司机时间重叠直接 409 拦截（验收标准第 4 条）
- **WebSocket 实时推送**：2s 广播，断线自动降级轮询 + 重连
- **ETA**：叫车单/司机端/地图车辆标签显示预计到达分钟数（站序推算）
- **大屏看板** `/board`：在线率、准点率（发车延迟 ≤5min 算准点）、班次完成率
- **轨迹回放** `/track`：基于 `arrivals` 到站明细，高德地图逐站回放

## 6. 已知问题

- 司机登录只验手机号无密码（内网信任模型），上线前换短信验证码（见 D11 / R4）。
- ETA 是站序推算非路径规划，精度有限（见 D14）。
- 乘客只能选**固定站点**上下车，不能填自由地址（与 Q3 一致，若需要再加）。
- 浏览器刷新后乘客端会记住上一次叫车单（localStorage），点"取消叫车"或送达后点"再叫一次"清除。
- 微信通知、小程序、弱网离线补传未做（阶段 2 剩余项，见 `03-roadmap.md`）。
