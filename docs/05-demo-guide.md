# 05 · DEMO 使用说明

**版本：v0.1（2026-11-11）** ｜ 跑在绿联 NAS 的 Hermes 容器里，容器内 8010、宿主已映射 8010。

## 1. 打开

| 端 | 地址 | 建议设备 |
|---|---|---|
| 调度端 | `http://192.168.1.210:8010/dispatcher` | 电脑浏览器 |
| 司机端 | `http://192.168.1.210:8010/driver` | 手机浏览器（同一个 WiFi） |
| 乘客端 | `http://192.168.1.210:8010/rider` | 手机浏览器 |

打不开时依次排查：
1. 手机和 NAS 是否同一网段；
2. `curl http://192.168.1.210:8010/health`（在 NAS 上）—— 不通则容器内服务没起，看 `logs/server.log`；
3. 宿主 8010 是否被别的服务占用（`docker ps` 看端口映射）。

## 2. 三分钟演示脚本（建议两人：电脑 + 手机）

1. **调度端**先开，看到 4 辆车停在起点站、7 个今日班次（08:00 环线 A … 18:00 接驳 B）。
2. **手机开乘客端**：起点选「园区环线 A · 南门」，终点选「食堂」，人数 2，点**叫车**。
   → 页面立刻变成「等待接单」。
3. **电机开司机端**（或另开一个浏览器窗口）：下拉选「张伟」→ 点**开始发车** →
   点站点「3. B 栋」= 到站上报。
4. 回**调度端**：车辆卡片与地图上「D1234」已经跳到 B 栋，
   右侧「待处理叫车」出现这条单 → 点**指派车辆** 或让司机端点**接单**。
5. **司机端**点「已接到乘客」→ 乘客端状态变「已上车」；再点「送达完成」→ 乘客端显示已送达。
6. 调度端底部**事件日志**能看到全过程：`arrive / ride_new / accepted / boarded / done`。

> 位置是"到站触发"：车不动位置就不动，这正是设计（见决策 D6）。

## 3. 常用命令

```bash
cd /mnt/projects/Dispatcher

./run.sh                      # 本地起服务（带热重载，默认 8010）
.venv/bin/python scripts/reset_demo.py   # 清空演示数据、重新播种
tail -f logs/server.log       # 看服务日志

# Docker 部署（在 NAS 宿主上）
docker compose up -d --build
```

看门狗：cron `dispatcher-demo-watchdog`（每 10 分钟）跑 `/opt/data/scripts/ensure-dispatcher.sh`，
探活 `127.0.0.1:8010/health`，挂了自动拉起，健康时静默。

## 5. 这一版没做

- 登录与权限（司机靠下拉切换）
- 台账增删改（车辆/司机/线路/站点要改得动种子数据或库）
- 地图上画线路生成站点、排班冲突检测
- 真·腾讯地图（等 key，现在自绘示意图）
- ETA 估算、"附近车辆"

## 6. 已知问题

- 乘客只能选**固定站点**上下车，不能填自由地址（与 Q3 一致，若需要再加）。
- 司机选不同班次时位置只更新到被点的那一班（`shift_id` 已按班次隔离，符合预期）。
- 浏览器刷新后乘客端会记住上一次叫车单（localStorage），点"取消叫车"或送达后点"再叫一次"清除。
