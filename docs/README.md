# 文档地图

本目录是 Dispatcher 项目的**单一真相源**。需求、架构、决策一律在这里，不在聊天记录、不在别处的笔记。

## 文档清单

| 文件 | 用途 | 状态 |
|---|---|---|
| `01-requirements.md` | 角色、业务流程、功能范围、验收标准、Q1–Q11 回答记录 | 已定稿 v2 |
| `02-architecture.md` | 技术选型、数据模型、接口清单、部署、已知限制 | as-built |
| `03-roadmap.md` | 阶段划分与里程碑进度 | 进行中 |
| `04-decisions.md` | 决策记录，一条决策一节，追加不改写历史 | 持续追加 |
| `05-demo-guide.md` | DEMO 打开方式、演示脚本、命令、已知问题 | v0.1 |

## 写作约定

1. **编号前缀**按阅读顺序：需求 → 架构 → 路线图 → 决策。新增文档取下一个空号。
2. **状态标注**：每份文档顶部标 `草稿 / 评审中 / 已定稿`。定稿后大改要先在 `04-decisions.md` 记一条。
3. **不确定的就标不确定**：用 `【待确认】` 标记，不要写成既定事实。所有待确认项汇总到 `01-requirements.md` 末尾的清单并编号（Q1、Q2…），便于逐条逐项拍板。
4. **决策 vs 需求**：需求写"要什么"，架构写"怎么实现"，决策写"为什么选这个、放弃了什么"。
5. 中文书写；专有名词、字段名、API 路径保留英文原文。
