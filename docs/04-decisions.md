## D10 · 实时：3 秒轮询 →（阶段2）WebSocket 推送 + 轮询兜底
- 日期：2026-11-11 ｜ 状态：已升级为 WebSocket（原轮询保留为降级路径）
- 决策：`/ws` 每 2s 广播全量 state（内容无变化且有 dirty 标记才发）；写操作后 `hub.bump()` 下一 tick 立推。

## D11 · 登录鉴权：简易 token（阶段1收尾已实装）
- 日期：2026-11-11 ｜ 状态：已采纳（替代原"不做登录"）
- 决策：司机=登记手机号登录（无密码，内网信任模型）；调度员=共享口令（`DISPATCHER_PASSWORD`，
  未配置则首启随机生成落盘 `data/.dispatcher_pass`，0600）。
  token = base64(payload).HMAC-SHA256 签名，12h 过期；密钥随机生成存 `data/.token_secret`。
  乘客端免登录（含叫车/取消）；台账/排班/看板/轨迹仅调度员；司机只能操作自己的班次与接单。
- 风险：司机无密码，内网可冒名。**真实上线前**升级为短信验证码 + 调度员独立账号（R4）。

## D14 · ETA 估算（阶段2）
- 日期：2026-11-11 ｜ 状态：已采纳
- 决策：不接高德路径规划 API，用站序推算：`(目标站序-当前站序) × 每站均时`，
  每站均时 = `duration_min / (站数-1)`。环线用模运算处理跨圈。跨线路叫车不显示 ETA。
- 理由：到站触发定位（Q6）下没有连续 GPS，路径规划精度无意义；站序推算与数据模型一致且零成本。
