# 04 · 决策记录 (ADR)

格式：一条决策一节，**追加不改写历史**。后来推翻的决策标 `已废弃` 并指向新决策，不删除。

模板：

```
## Dn · 标题
- 日期：
- 状态：已采纳 / 已废弃（见 Dm）/ 待定
- 背景：
- 决策：
- 放弃的方案与原因：
- 影响：
```

---

## D1 · 文档先行，文档入仓库
- 日期：2026-11-10
- 状态：已采纳
- 背景：项目刚起步，神朱要求所有相关文档集中存放；先出方案再实施是本项目一贯做法。
- 决策：需求、架构、路线图、决策全部写在 `/mnt/projects/Dispatcher/docs/`，与代码同仓库；聊天记录不作为需求真相源。
- 放弃的方案：本地笔记 / 网盘文档 —— 与代码分离，易失同步。
- 影响：任何范围变更都先改文档再改代码。

## D2 · 最小工程量先出 DEMO
- 日期：2026-11-10
- 状态：已采纳
- 背景：神朱不参与技术细节，要求先看到能跑的东西再迭代。
- 决策：单体 FastAPI + SQLite + 简单前端；不做微服务、不上消息队列、不做自动排班算法，功能稳定后再升级。
- 放弃的方案：一步到位上 Postgres + PostGIS + 前后端分离 + 自动排班 —— 工程量与不确定性过高。
- 影响：数据量或地理查询成为瓶颈时，按 `02-architecture.md` 的迁移路径升级。
